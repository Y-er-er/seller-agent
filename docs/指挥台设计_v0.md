# 商家售后指挥台设计 v0

## 一、定位

**主产品形态**：商家管理员在这里**实时看到买家的售后问题**，并**指挥智能体**处理——
指派、介入、确认，人始终在环。

## 二、信息架构（桌面端，商家后台）

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏：商家名 · 今日待处理 N · 智能体状态（运行中/暂停）          │
├──────────┬───────────────────────────────────────────────────┤
│ 左侧导航  │  收件箱 / 处理中 / 待确认 / 已完结 / 已转人工          │
│          ├───────────────────────────────────────────────────┤
│ 收件箱    │  售后问题列表          │   单笔详情面板                │
│ (badge)  │  ┌───────────────────┐ │  ┌─────────────────────┐   │
│          │  │ 订单 · 买家 · 诉求  │ │  │ 对话流（买家↔智能体） │   │
│          │  │ 状态 · 时间        │ │  │ 动作日志（智能体可见性）│   │
│          │  └───────────────────┘ │  │ 事实面板（订单/物流/举证）│   │
│          │  （选中 → 详情）        │  │ 判定结论卡 + 处置动作     │   │
│          │                        │  │ [指派智能体][自己处理]   │   │
│          └────────────────────────┘  └─────────────────────┘   │
└──────────────────────────────────────────────────────────────┘
```

## 三、状态机与指挥动作

```
待处理(queued) ──指派──▶ 智能体处理中(agent_running) ──出结论──▶ 待确认(awaiting_confirm) ──确认──▶ 已完结(resolved)
     │                          │                                  │ 驳回/失败
     │ 自己处理                  │ 介入                              ▼
     └──────────────▶ 已转人工(escalated) ◀──────────────────────┘
```

| 指挥动作 | 语义 | 何时可用 |
| - | --- | --- |
| **指派** | 把单交给智能体全权处理 | 待处理 |
| **介入** | 管理员接管，暂停智能体自主 | 处理中 |
| **确认** | 批准智能体的判定（含退款/补发） | 待确认 |
| **驳回** | 否决判定 → 转人工/改判 | 待确认 |
| **自己处理** | 管理员亲自回复，不派智能体 | 待处理 |

## 四、判定结论呈现（三类卡片）

| 结论 | 卡片 | 关键信息 |
| - | --- | --- |
| **退款** | ✅ 同意退款 ¥xx | 金额 + 依据折叠 + `[确认退款]` |
| **补发** | 📦 同意补发 | 补发说明 + `[确认补发]` |
| **拒绝** | ⛔ 不予处理 | 理由（买家语言）+ `[确认拒绝]` |

> 依据折叠内是**买家语言**（"物流显示 7 天前已签收"），不含规则代号/阈值——与买家侧 H5 同口径。

## 五、详情面板两条硬需求（2026-10-15 用户补充）

1. **完整对话历史对管理员可见**：管理员能看到智能体与买家的**逐条历史消息**（双向、带时间戳），用于判断"智能体问得对不对"，也是介入/改判的依据；
2. **举证材料点击可查看**：详情面板的举证材料以**缩略图**呈现，点击**放大查看**原图。

## 六、设计原则（沿用，不重复造轮子）

1. **智能体可见**：详情面板展示智能体的**动作日志**（真实做了什么），不是装饰进度条；
2. **人始终在环**：指派/介入/确认权都在人，智能体只在被指派后自主；
3. **不编造**：无排队系统 → 不显示"预计接入时间"；无到账时间 → 显示"以平台处理为准"；
4. **关键节点回执**：判定结论 + 资金/库存动作，必须回到管理员确认（L2）或回执（L1）。
