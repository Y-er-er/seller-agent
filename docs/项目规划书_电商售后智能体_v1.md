### 1.2 一句话定位

> **面向商家的售后智能体：买家售后问题实时进入后台，管理员指挥智能体处理指定单，智能体自主与买家沟通、调工具取证、判定（拒绝 / 退款 / 补发），关键结果回执给人，人随时可介入。**
>
> 判定结论仍由确定性规则引擎给出，模型只负责「把过程做好、把事务办成」。

### 1.3 业务背景与真实痛点

电商「仅退款」场景的三重矛盾：

| # | 角色     | 痛点                                                                                     |
| - | ------ | -------------------------------------------------------------------------------------- |
| 1 | **买家** | 申请入口是**表单**——要买家自己选"退款原因""退款金额"，而这恰是他最不专业的判断。结果是"该怎么归类、该补什么材料"的负担被推给用户，导致材料不足、反复沟通、体验差 |
| 2 | **平台** | 判定规则需要**可信事实**（物流状态、举证图片、历史行为），但这些事实散落在对话之外，只能靠人工追问补齐                                  |
| 3 | **人工** | 仲裁员拿到的是**一条结论**，看不到"智能体问了什么、依据是什么"，只能从头再查一遍                                            |

**一句话**：缺的不是判定规则，而是**推进这件事的全过程**。

### 1.4 目标与成功指标

#### 1.4.1 分层目标

| 层次         | 目标                                                    | 衡量方式                    |
| ---------- | ----------------------------------------------------- | ----------------------- |
| **本期（P1）** | 让买家能**用对话**完成一次售后申请：描述问题 → 被追问 → 上传材料 → 拿到结论 → 必要时转人工 | 全流程 ≤20 轮走通（H5，mock 数据） |
| 中期（P2—P3）  | 人工介入台可用：仲裁员**只凭卷宗**即可决策；取证策略收敛、话术稳定                   | 卷宗完整性验收 + 澄清轮数下降        |
| 长期（P4+）    | 接真实数据与通道（订单/物流接口、COS、小程序/IM），具备上线条件                   | 真实单跑通                   |

#### 1.4.2 成功指标（KPI）

> ⚠️ 以下为**设计目标值**，非实测值。P1.4 成本实测与 P1 验收后回填实际值。

| 指标        | 定义                       | 目标                 | 采集点                                  |
| --------- | ------------------------ | ------------------ | ------------------------------------ |
| **对话完成率** | 给出结论（`DECIDED`）的会话 / 总会话 | ≥ 60%（其余为合理转人工）    | `conversation_message` + 会话状态        |
| **平均轮数**  | 完成会话的平均往返轮数              | ≤ 12 轮（硬上限 20）     | 会话状态机计数                              |
| **转人工率**  | `ESCALATED` / 总会话        | 观察项，不设目标（业务决定）     | `guardrail_event`                    |
| **澄清有效性** | 同一槽位被追问 ≥2 次的会话占比        | ≤ 15%              | `guardrail_event(type=slot_missing)` |
| **单会话成本** | 等效消耗金额                   | 由 P1.4 实测产出后**配死** | 用量记录表                                |
| **解释可读性** | 人工抽检"解释是否让人看懂"           | 抽检 20 例，≥ 90% 合格   | 人工评审                                 |
| **判定一致性** | 相同输入 → 相同结论（判定层）         | **100%**（红线，不许有例外） | 回归基线 267 项                           |

### 1.5 范围边界

**做**：买家侧对话入口（H5）· 查单/查物流/查进度 · 多轮澄清与取证 · 提交判定 · 结论解释 · 随时转人工 · 人工介入台（卷宗）· 成本闸门 · 全链路审计。

**不做（负面清单，防止范围蔓延）**：

- ❌ **不把结论交给模型**——赔不赔、赔多少，永远由规则 + 人工决定；
- ❌ **不做质量判定**——质量问题一律转人工（业务红线；模型只能描述可见事实）；
- ❌ **不接真实生产库**（P4 之前一律 mock）；
- ❌ **不做商家侧完整入口**（R6：商家只可见自己订单的脱敏片段）；
- ❌ P1 不做：视觉理解 · 小程序/IM · 多语言 · 真实资金动作。

### 2.2 为什么必须重定形态（判据对照）

业界对「智能体」的判别线是**控制权归属**：**代码编排模型 = 工作流；模型决定代码走哪条路 = 智能体**。

| 判据      | v2.x 事实                                      |
| ------- | -------------------------------------------- |
| 输入      | 结构化表单；退款原因由前端下拉选择                            |
| 控制流     | 11 节点 + 条件边**全部硬编码**（纯 Python 路由函数）          |
| 工具      | 直接 `await` 函数调用；无 tool schema、无 `bind_tools` |
| 记忆 / 多轮 | 一次 `ainvoke` 跑到 END；检查点存**图状态**，不是对话         |
| 模型      | `LLM_ENABLED=false`；唯一接入点默认关闭                |
| 前端      | 5 个视图**全是后台控制台**；「提交申请」还需注入 mock，属测试工具       |

### 2.3 结论

**v2.x 是一套合格的判定后端，但不是智能体产品。**
  
问题不在实现质量，而在**产品形态缺失**：没有对话、没有工具自主调用、没有多轮，界面服务的是运营而非当事人。

→ **资产保留，形态重定。** 已建成的判定链路不再充当"产品主干"，而是成为智能体调用的**一个工具**（`submit_for_decision`）。

## 三、目标形态

### 3.1 三类角色 / 三个入口

| 角色           | 入口                      | 本期           |
| ------------ | ----------------------- | ------------ |
| **买家**（当事人）  | 对话入口（订单页 / 售后页 / IM 内嵌） | ✅ **主攻（H5）** |
| **平台仲裁员**（人） | 人工介入台（卷宗）               | ✅ P2 改造      |
| 商家           | 仅可见**自己订单**的脱敏片段        | ❌ 不做完整入口（R6） |

> **关键认知**：控制台**不是错的设计**，但它服务的是**人**，不是智能体界面。
>   
> 智能体的界面必须长在**用户的售后业务流里**。

### 3.2 买家侧对话入口（P1 主攻）

| 区域        | 内容                                          |
| --------- | ------------------------------------------- |
| **订单上下文** | 商品、订单号、申请金额、物流状态、剩余时限——**会话绑定这笔单**，用户不必重复描述 |
| **对话流**   | 富消息：文本、图片/视频、金额卡片、**按钮式快捷澄清**               |
| **进度时间线** | 已受理 → 待补证 → 待人工 → 已出结论（带时间戳）                |
| **可行动区**  | 上传证据、查看进度、**随时转人工**（不需要"问"出来）               |
| **转人工**   | 带上完整上下文（对话摘要 + 材料 + 疑点 + 规则依据），人工不必再问一遍     |

**必备的三类护栏反馈**（对应 §9.1）：

1. 超长提示：`"内容较长（xxx 字），请精简到 200 字内重发"`（**不计轮次**）；
2. 轮数耗尽：`"本次咨询已达上限，已转人工，请等待客服接入"`；
3. 成本暂停：`"系统当前暂停接待，已为您转人工"`。

### 3.3 平台侧人工介入台（现有控制台改造）

保留现有 5 视图中的 4 个，改造要点：

1. **队列项扩展为「卷宗」**：对话摘要 + 材料（可预览）+ 命中规则与逐条依据 + 疑点 + AI 建议；
2. **会话还原**：看到买家与智能体的完整对话（判断"问得对不对"）；
3. **人工动作**：采纳 / 改判（**理由必填**）/ 要求补充 / 重试处置 / 关闭；
4. **移除**「提交申请」视图（测试工具，改由对话入口驱动）；
5. **「口径问答」tab 并入对话入口**后删除。

> 卷宗的字段级定义见《设计_人工介入台卷宗视图_v0.1》——9 个分区，其中「系统风险标签」与「模型风险提示」**物理分栏**。

### 3.4 两个界面的职责边界

```
买家侧（对话入口）                        平台侧（人工介入台）
┌──────────────────────┐                ┌──────────────────────────┐
│ 订单上下文卡片        │                │ 待介入队列                │
│ 对话流：追问/取证/解释 │  ──转人工──→  │ 卷宗：事实+证据+疑点+建议  │
│ 进度时间线/可行动按钮  │                │ 采纳/改判/要求补充/重试     │
└──────────────────────┘                └──────────────────────────┘
          ↑                                          ↑
          └────────── 智能体内核（对话/工具/记忆）────┘
                              ↓ 委托判定（submit_for_decision）
                规则引擎 + 审计 + 双闸门（v2.x 成果，原样复用）
```

**两个界面职责分明**：对话入口 = **当事人的界面**；人工介入台 = **人的界面**（是运营/仲裁工具，**不是**智能体界面）。

## 四、设计原则与红线

### 4.1 根本原则：自主性落在「过程」，确定性落在「结论」

| 维度            | 谁决定          | 具体                                          |
| ------------- | ------------ | ------------------------------------------- |
| **对话**        | **模型**       | 问什么、怎么问、何时追问、何时结束                           |
| **取证**        | **模型 + 策略**  | 要哪些材料、够不够（策略给硬性下限，模型在范围内裁量）                 |
| **工具**        | **模型**       | 调什么、调几次（限白名单、限次数）                           |
| **解释**        | **模型**       | 用业务语言解释结论与依据（**事实必须来自 `hit_details`，不可改写**） |
| **赔不赔 / 赔多少** | **规则 + 人工**  | 模型**不参与**；命中红线一律转人工                         |
| **资金动作**      | **规则 + 双闸门** | 模型**不得**直接触发退款                              |

> 这条原则同时满足两个硬要求：**是真智能体**（过程由模型自主）、**结论可复现**（判定仍由规则给出）。

### 4.2 七条红线（不可让步）

1. **不做质量判定**：质量问题一律转人工；模型只能描述可见事实。
2. **规则引擎不暴露为模型工具**：模型只能"请求判定"，不能"改写规则 / 阈值"。
3. **资金动作双闸门**：`SHADOW_MODE=false` **且** `DISPOSAL_ENABLED=true` 才具备资格，且带幂等键。
4. **同输入同结论**：仅约束**判定**；对话过程允许非确定性。
5. **个人信息最小化**：模型调用可全局关闭；图片/对话外送需单独评估。
6. **成本闸门**：`LLM_ENABLED` 总开关 + 护栏参数（§9.1）。
7. **成本控制不侵蚀智能体架构**：**模型自主决定是核心**——意图理解、工具选择、追问策略、提交时机
   **由模型自主**，不得为省成本改为线性编排或人为限死调用次数。成本控制只作用于**运行策略**（§9.4）。

### 4.3 「推断不污染事实」——机制保障，而非约定

| 措施            | 说明                                                               |
| ------------- | ---------------------------------------------------------------- |
| **槽位物理隔离**    | 模型抽取的槽位**不进入规则事实字典**（`FACT_FIELDS` 不含槽位字段）→ 从机制上杜绝"推断参与判定"       |
| **冲突以权威数据为准** | 买家陈述与取数结果冲突时（如"没收到" vs 物流已签收），**以权威数据为准并记录冲突**，交规则/人工，**不由模型调和** |
| **卷宗分区**      | 卷宗中「系统风险标签」（规则引擎算）与「模型风险提示」（独立分区）**物理隔开、不同配色**，并标注"不参与判定"        |
| **只读不可改**     | 卷宗中的模型抽取参数**不提供编辑入口**（R2）——防止人工改推断污染事实、破坏留痕口径                    |

## 五、系统架构

### 5.1 四层结构

```
L1  H5 对话页（买家）
      │  SSE（流式回复）
L2  对话内核
      ├─ 护栏（轮数 / 字数 / 路由到人工）
      ├─ 成本闸门（调用前预检 + 调用后记账）
      ├─ agentic 循环（模型 ⇄ 工具，手写 StateGraph）
      ├─ 记忆（会话上下文 + 工单阶段）
      └─ 槽位抽取 + 参数装配
      │  调用工具 submit_for_decision
L3  判定后端（v2.x 现有图原样复用）
      intake → 取数 → 举证 → judge → risk → dispose → audit
      │  返回：结论 + 命中规则 + 逐条依据
L4  数据层
      conversation_message / case_slot / guardrail_event（新增）
      decision_audit（加 3 字段）· checkpointer（沿用）
```

### 5.2 层间约束（调用规则，不允许变通）

| 约束         | 说明                                                                                                              |
| ---------- | --------------------------------------------------------------------------------------------------------------- |
| **单向调用**   | L2 **只能**通过 `submit_for_decision` 触达 L3，**不得直接读判定内部状态**                                                         |
| **判定层无状态** | L3 **不知道对话的存在**（保持无状态、可复现）                                                                                      |
| **循环必须手写** | L2 的对话循环**手写 LangGraph 子图**，**不用 `create_agent`**——成本预检要插在**每次模型调用前**、审计要落在**每次工具调用后**、轮数要有**硬终止**；这三件事必须"不可绕过" |
| **命名空间隔离** | 对话线程的检查点与判定线程**分开**，互不污染                                                                                        |

### 5.3 与现有判定后端的关系

| 关系   | 说明                                            |
| ---- | --------------------------------------------- |
| 调用方向 | 对话层 → 判定层（**单向**）                             |
| 关联键  | `case_id` = 受理号 = 判定图 `thread_id`（三处同值）       |
| 命名空间 | 对话线程与判定线程分开                                   |

## 六、功能规划

### 6.1 工具白名单（模型可调用的全部能力）

| 类型     | 工具                                        | 约束                    |
| ------ | ----------------------------------------- | --------------------- |
| 读      | 查订单 / 查物流 / 查买家画像 / 查规则口径 / 查工单进度 / 查历史工单 | 只读；异常返回"取不到"，**不得编造** |
| 写      | 登记证据 / 发起补证 / 催办 / 升级人工                   | 幂等；**全部留痕**           |
| 判定     | 提交判定（调用现有图）                               | 一次会话内可重复，结论由规则给出      |
| **禁止** | 直接退款 / 改规则 / 改阈值 / 任意 SQL / 任意 URL 抓取     | **绝不暴露给模型**           |

**P1 落地六个工具**：`query_order` · `query_logistics` · `query_case_progress` ·
  
`register_evidence` · `submit_for_decision` · `escalate_to_human`。

**每个工具都必须记审计**：谁触发（模型）、入参摘要、耗时、结果摘要、是否成功。

### 6.2 多轮取证策略（"过程自主"的落点）

- **策略给下限**：如"质量主张 ≥2 张图 + 1 段视频""补证时限 48h"——由**配置**给出，**不由模型临场决定**；
- **模型在范围内裁量**：是"再补一张整体照"还是"够了，提交判定"；
- **催办与超时**：到时限未补证 → 自动提醒 → 超时升级人工；
- **防空转**：单会话轮数上限、单轮工具调用上限、同槽位追问上限。

### 6.3 会话状态机

| 状态           | 含义            | 可迁移到                                     |
| ------------ | ------------- | ---------------------------------------- |
| `CREATED`    | 已建会话，未开始      | `CLARIFYING`                             |
| `CLARIFYING` | 正在澄清诉求与事实（多轮） | `COLLECTING` / `SUBMITTED` / `ESCALATED` |
| `COLLECTING` | 正在收证据         | `SUBMITTED` / `ESCALATED`                |
| `SUBMITTED`  | 已提交判定，等待结论    | `DECIDED` / `ESCALATED`                  |
| `DECIDED`    | 已出结论并告知买家     | `CLOSED`                                 |
| `ESCALATED`  | 已转人工（终态，等人工）  | `CLOSED`                                 |
| `CLOSED`     | 结束（含超时关闭）     | —                                        |

**迁移守卫（硬条件，任一不满足即不放行）**：① 会话轮次 < 20；② 成本闸门未暂停；③ 会话未处于终态。

**升级人工的触发源**（每个都必须写明原因并落 `guardrail_event`）：
  
轮数耗尽 · 字数二次超长 · 成本闸门暂停 · 判定返回 `to_human` · 工具连续失败 · 买家主动要求。

### 6.4 记忆

- **会话内**：对话历史 + 已提交材料 + 当前阶段（**避免重复问同一件事**）；
- **跨会话**：该买家的历史工单摘要（供**风险提示**），**但不作为判定依据**。

### 6.5 人工介入台（卷宗）

**9 个分区**：摘要条 / 基本信息 / **风险标签与模型提示（两个独立分区）** / 命中规则 / **逐条依据（中文化）** /
  
**模型抽取参数（推断·只读）** / **对话历史（含工具调用）** / 举证材料 / 审计与用量 ＋ 底部人工动作区。

**三条设计原则**：**事实与推断分离** · **每个字段可回溯** · **人工决定必须留痕**。

> 字段级定义与数据来源映射见《设计_人工介入台卷宗视图_v0.1.md》。

### 6.6 成本闸门（P1 **第一个**要实现的东西）

| 级别      | 阈值                                  | 动作                    |
| ------- | ----------------------------------- | --------------------- |
| 免费额度优先  | **由 `.env` 配置**（默认 100 万 token） | 额度内优先消耗；余额按**本地累计估算** |
| 额度到期（**可选**） | 默认留空 = 不启用 | 若填了且已到期 → 暂停（到期后额度失效转按量付费） |
| 额度基线（**可选**） | 默认 0 | 真实已用 = 基线 + 本项目累计；额度值属**外部事实**，换模型即失效 |
| **预警线** | **¥0.1（等效消耗）**                      | **立即暂停新会话 + 向用户汇报**   |
| 月度硬上限   | **¥200**                            | 停用对话入口（转人工兜底）         |


**暂停语义（写死）**：新会话**拒绝创建并明确提示**（不静默失败）；**进行中的会话允许收尾**——
  
能出结论就出结论，否则直接转人工；健康端点暴露 `cost_gate = active|paused` 与当月消耗。

**计量口径**：`input_tokens` / `output_tokens` × **官方单价** → 等效消耗金额；**单价入 `.env`**（纪律 9）。

## 九、护栏与成本控制

### 9.1 护栏参数（**已定稿，不可放宽**）

| 参数       | 取值                                  | 触发后的行为                                              |
| -------- | ----------------------------------- | --------------------------------------------------- |
| 模型       | **qwen3.7-plus**（国产高性价比）            | —                                                   |
| 单会话轮数上限  | **20 轮**                            | 第 20 轮：**能给结论就给结论并结束**；否则**直接转人工**，必须明确告知「已转人工，请等待」 |
| 单条消息长度上限 | **200 字**                           | **首次超长 → 提示精简重发（不计轮次）**；**再次超长 → 转人工**              |
| 视觉理解     | **P1 关闭**（`VISION_MAX_IMAGES=0`）    | P3 单独评估预算                                           |
| 数据来源     | **mock**，绝不接真实生产库                   | P4 前不接                                              |
| 交互通道     | **网页 H5**                           | 小程序 / IM 延后到 P4                                     |
| 月度成本上限   | **¥200**                            | 停用对话入口（转人工兜底）                                       |
| 预警线      | **¥0.1（等效消耗）**                      | **立即暂停新会话 + 汇报**                                    |
| 免费额度     | **由 `.env` 配置**（默认 100 万 token） | **优先消耗**                                            |

> **两条设计裁决（已采纳）**：① 超长消息**不许一票否决**（首次只提示、不计轮次）；
>   
> ② **轮数耗尽语义写死**（必须"给结论或转人工 + 明确告知"）。

> ⚠️ **待澄清（口径，阻塞 P1.1）**：¥0.1 是**等效消耗**还是**实际扣费**？
>   
> 免费额度覆盖期间**实际扣费恒为 0** → 按"实际扣费"计，该线**永不触发**；
>   
> 按"等效消耗"（token × 单价）计则量级不大，**一开跑就可能暂停**。
>   
> 本规划按「**等效消耗**」处理（只有这样才能起到"防自动扣费"的作用），待确认。

### 9.2 护栏实现点

| 护栏             | 检查时机                | 留痕类型                        |
| -------------- | ------------------- | --------------------------- |
| 轮数 ≤ 20        | **每次收到买家消息时**（增量校验） | `round_limit`               |
| 单条 ≤ 200 字     | 收到消息时（**在计轮之前**）    | `msg_too_long`（含第几次）        |
| 成本预警 / 月度上限    | **每次模型调用前**         | `cost_warning` / `cost_cap` |
| 单轮工具调用上限（建议 3） | 每轮内                 | `tool_limit`                |
| 同槽位追问上限（建议 2）  | 每次追问                | `slot_missing`              |
| 会话静默超时（建议 24h） | 定时任务                | `session_timeout`           |

### 9.3 成本控制的三道措施

1. **闸门前置预检**：调用前检查，不是事后统计（否则"已经花了才发现"）；
2. **测试桩优先**：**能在桩上验的绝不在真机上验**——离线单测覆盖全部护栏分支；
3. **护栏实测调参**：先跑 100 次模拟会话测出 P50/P95，再把阈值**配死**。


### 9.4 成本控制的正确落点：**运行策略**，而非架构

> **前提（不可动摇）**：**模型自主决定是智能体的核心**。对话过程中——理解意图、选择工具、
> 决定是否追问、判断何时提交判定、组织回复——**一律由模型自主决策**。
> 成本控制**不得**通过"改为确定性线性编排""一次往返硬限 1 次调用"来实现：
> 那不是成本优化，而是**取消智能体**。
> （此前一度写下"一次往返最多 1 次模型调用"，属**把成本约束误用到架构层**，已废弃。）

**三层归属——先划清「谁有权做决策」**

| 层 | 归属 | 理由 |
| - | --- | --- |
| **决策层**：意图理解 · 工具选择 · 追问策略 · 提交时机 · 回复文案 | **模型自主** | 智能体的本质；**不因成本让步** |
| **判定层**：规则求值 · 阈值 · 结论 | **确定性代码** | 出自**可复现与可审计**要求（红线 2「规则引擎不暴露为工具」），**与成本无关** |
| **呈现层**：护栏文案 · 进度播报 · 依据格式化 | 可确定性生成 | 不含判断成分，无需调用模型；**属实现优化，不动架构** |

**成本控制措施——全部作用于运行策略**

| # | 措施 | 说明 |
| - | --- | --- |
| 1 | **默认关闭 + 显式开启** | 对话层模型独立开关；不需要时不产生任何消耗 |
| 2 | **离线优先：桩上跑通完整 agentic 循环** | 模型桩驱动「选工具 → 多轮往复 → 提交判定」**全链路**，零调用即可回归 |
| 3 | **真机验证最小化** | 只验「桩覆盖不到」的部分（真实模型的理解与措辞），限 N 次 |
| 4 | **上下文工程** | 只送最近 N 轮 + 槽位摘要，不整段回灌；工具返回做摘要；系统提示精简（**长上下文是成本大头**） |
| 5 | **成本闸门兜底**（§9.1） | 花超即停——**它是兜底，不是"少调用"的替代方案** |

> **一句话**：省的是"**不必要的调用与冗余上下文**"，
> **不是**"模型的自主决策权"。**离线桩测试是验证手段，不是架构妥协。**

### C. 决策记录汇总

**Q1—Q5（范围与护栏）**：qwen3.7-plus · 单会话 ≤20 轮 · 继续 mock（不接生产库）· 网页 H5 · P1 关闭视觉。

**卷宗 R1—R6**：改判理由**必填** · 模型槽位**只读不可改** · 风险标签**由规则引擎生成**（模型提示独立分区）·
  
导出**默认禁止走审批 + 脱敏水印** · 对话历史**保留 90 天** · **只对平台仲裁员开放**。

**设计裁决**：超长消息首次提示（不计轮次）、再犯转人工 · 轮数耗尽必须给结论或转人工并明确告知。

**架构裁决**：判定图**降级为工具** `submit_for_decision` · 对话循环**手写 StateGraph**（不用 `create_agent`）·
  
槽位**物理隔离**于规则事实字典（`FACT_FIELDS`）。
