# 订单管理与客服会话 · 实施方案 v1

日期：2026-10-21。状态：前端原型已获用户确认；本地 MVP 代码已实现，六张 MySQL 表已创建并核对；专用数据烟测已通过并清理。

## 目标与边界

形成“买家咨询 → 查询订单 → AI 或人工回复 → 必要时转售后”的闭环。当前没有平台授权，因此订单工作台只管理本系统持有的订单快照。每笔订单必须展示 `source`：`demo`（演示）或 `imported`（商家导入）。导入订单不能在本系统内假称已向原平台发货、退款或改价。

现有 `OrderSnapshot`、`OrderItem` 与 `DataSource` 用于售后取事实，保留原有契约；新订单工作台使用独立的持久化仓储。暂不让导入订单自动进入现有售后判定链，直到订单归属、订单行选择及买家身份校验完成。

## 第一阶段：订单工作台后端

1. 新增 `merchant_order`、`merchant_order_line`、`merchant_order_event`。金额统一用整数分；订单号按 `seller_id + source + external_order_id` 唯一。订单行必须有稳定 `line_id`。记录导入时间、源订单时间和可追溯的状态事件。
2. 卖家登录后可通过 CSV 导入订单、分页查询、按订单号查看详情。前端将 CSV 转为结构化订单，后端仍做全部校验。导入相同键且内容相同返回既有订单；同键内容不同返回冲突，避免静默覆盖。禁止从导入接口改写订单状态。
3. `demo` 订单由独立演示入口生成，事件显式标 `simulated=true`；本阶段不开放模拟支付、发货、退款 API。
4. 对订单和订单行做严格校验：数量为正，金额非负，行实付之和与订单实付一致，行编号不得重复；导入限制条数与请求大小。
5. 新增迁移 SQL，但不自动执行。应用启动不自动建订单表；未迁移时订单接口明确报“订单表未初始化”，避免以空列表掩盖错误。

## 第二阶段：客服会话后端

新增 `service_conversation`、`service_message`、`quick_reply`，与现有 `conversation_case`（售后工单）分开。咨询可无订单；绑定订单时只允许属于该卖家的订单。状态为 `open / assigned / closed`，接待者为 AI 或人工。买家进线先进入收件箱；人工接管后 AI 不再对外自动发送，仍可草拟回复。快捷回复由卖家管理，发送时保留实际发出的正文及操作者。转售后要显式创建关联，不把咨询会话直接改名为售后工单。

第一版提供独立的本地演示咨询页，买家会话由随机令牌访问；卖家登录后在控制台接待。仅 `DATA_SOURCE=local` 开放公开演示入口。买家身份与订单关系未核验前，不向买家透露订单详情，也不允许仅凭订单号查询个人信息。真实渠道接入需另做鉴权与签名校验。

## AI 接入

已注册四个只读工具：列订单、看订单、列咨询状态、列快捷回复。咨询原文可能含个人信息，当前仅人工在页面查看，**不送模型**。客服对外发送只由人工完成。工具返回内容明确注明订单是本地快照；缺资料时如实回答。发送消息、转售后、修改订单等工具不在第一批开放。**真实模型调用属于付费操作，本轮未执行**，因此尚未宣称模型实测效果。

## 前端原型方案（待用户确认后实现）

卖家控制台左栏新增“订单”“客服”。订单页沿用现有三栏：中栏为搜索列表与 CSV 导入，右栏为订单详情与状态时间线；页首始终显示“演示／导入”来源标记和“仅本地记录”说明。客服页中栏为会话收件箱，右栏为消息；顶部显示当前接待者和“接管／结束”操作，输入区提供快捷回复入口。订单卡因买家身份未核验，**本批不向客服咨询挂载**。AI 浮窗保持现有位置与行为。

买家 H5 增加“咨询商家”入口；进线页先显示演示环境标识，未核验身份时仅显示本会话消息，不展示订单敏感字段。咨询转售后尚未实现，后续必须先补买家身份及订单行确认。

## 实施与验收顺序

已落地订单与客服后端、四个只读 AI 工具、卖家页和买家演示咨询页。离线验收覆盖输入校验、来源标记、CSV 一单多行分组及路由身份传递。六张 MySQL 表已创建并核对；专用数据烟测通过订单幂等、卖家隔离、客服消息持久化及客服隔离，测试记录按主键清理。尚未做浏览器手工验收或真实模型调用。咨询转售后、真实模型与平台联调属于下一批。

## MySQL 迁移说明（2026-10-21 已执行）

需在项目配置的 MySQL 库执行 `sql/order_schema.sql`、`sql/service_schema.sql`，共新增六张表。`python sql/apply_commerce_schema.py` 只预览；加 `--apply` 才建表并只读核对。脚本只有 `CREATE TABLE IF NOT EXISTS`，不修改现有表或历史订单；但会在真实数据库创建新对象，因此执行前需确认目标库与备份。应用不会自行执行这两份迁移。未执行时新接口返回 503 与缺表提示。
