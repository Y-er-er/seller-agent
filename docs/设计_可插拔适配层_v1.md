# 设计 · 可插拔适配层（数据源 / 存储 / 模型）v1

> **日期**：2026-10-16 · **性质**：设计（含代码骨架与迁移路径，待确认后实施）
> **用户提出**：保持真实业务 API 的接口契约，用 Mock 测项目；对象存储（腾讯云 COS）同理保接口、本地实现；生产时替换。**能否做成可插拔？**

---

## 一、结论

**可行，而且是正确做法——并且现在是最佳时机。**

理由三条：

1. **商品域还没开始写**，一次到位成本最低；等写完再改就是重构。
2. **取数侧已有半成品**（`ORDER_API_BASE` 存在与否决定走真实还是 mock），但形态是**配置分支**而非**可插拔**，正好借这次规整。
3. 这正是本项目"**无真实数据源也能跑通**"这一既有边界的工程化落点——把"边界声明"变成"可切换的实现"。

---

## 二、现状盘点（有代码证据）

以 `app/tools/order.py: fetch_order()` 为例：

```python
async def fetch_order(order_id: str) -> OrderSnapshot | None:
    if settings.order_api_base:                      # ← 分支一：真实 HTTP
        data = await get_json(settings.order_api_base, f"/orders/{order_id}")
        if data is None:
            return None
        return OrderSnapshot(...)                    # ← 映射逻辑 A
    row = _MOCK.get(order_id)                        # ← 分支二：进程内 mock
    if row is None:
        return None
    return OrderSnapshot(...)                        # ← 映射逻辑 B（与 A 重复）
```

**三个问题**：

| # | 问题 | 后果 |
| --- | --- | --- |
| 1 | **不是"可插拔"，是"配置分支"** | 每加一种数据源就要改业务函数，`if/else` 会越堆越多 |
| 2 | **映射逻辑写了两遍**（A 与 B） | 改一处忘另一处 → 两条通道产出的对象悄悄不一致 |
| 3 | **模式是隐式的**：配置为空即走 mock | 环境态**不可见**。生产若忘配 `ORDER_API_BASE`，系统会静默进入演示态——所有单都"查不到数据 → 转人工"，却没有一条告警，排查成本极高 |

> ⚠️ 注意：问题 3 **不会**把假数据当真实数据用（mock 查不到就返回 `None`，且演示夹具在配了真实 API 时会自动失效）。
> 真正的风险是**"你现在跑在什么模式"这件事看不见** —— 故障没有声音。

**已具备的良好基础**（不要推倒重来）：

- `http_client.get_json()` 已经把"取数失败一律返回 `None`、绝不抛异常"的语义收在一处 ✅
- `coerce_enum / coerce_float / coerce_datetime` 已把外部值的安全转换收在一处 ✅
- `llm_adapter.ChatModel` 已经是 Protocol + 桩/真两实现的形态 ✅（模型侧已经可插拔了）
- `.env` 里 `ORDER_API_BASE / LOGISTICS_API_BASE / AFTERSALE_API_BASE / COS_*` 占位都已存在 ✅

## 三、三个该抽象的插拔点

| 插拔点 | 端口 | 开发期实现 | 生产期实现 | 为什么该抽 |
| --- | --- | --- | --- | --- |
| **业务数据源** | `DataSource` | 进程内夹具（`_MOCK`） | 真实只读 HTTP | 开发与生产**必然不同**（无授权、无客户） |
| **对象存储** | `ObjectStorage` | 本地 `backend/data/uploads/` | 腾讯云 COS | 同上；本地零依赖、云有流量费 |
| **模型服务** | `ChatModel` | 脚本化桩 | 千问 / 其它 | 已实现，只需挪到端口层统一 |

## 四、**不该**抽象的（防过度设计）

| 不抽 | 理由 |
| --- | --- |
| MySQL / repo 层 | 开发与生产**用的是同一种库**；抽了只有一个实现，是纯负担 |
| Web 框架 / 路由 | 同上 |
| 规则引擎 / 判定图 | 纯计算，无外部依赖 |

**判断标准一句话**：**只抽「开发环境与生产环境必然不同」的东西。** 只有一种实现的抽象，是负债不是资产。

## 五、设计

### 目录结构

```
backend/app/
├── ports/                     【新增】端口层（契约）
│   ├── __init__.py            只导出 get_datasource() / get_storage() / get_model()
│   ├── datasource.py          DataSource 协议 + 三个 fetch 方法
│   ├── storage.py             ObjectStorage 协议
│   ├── model.py               ChatModel 协议（从 chat/llm_adapter 迁入）
│   └── factory.py             按配置构造并缓存实例
├── adapters/                  【新增】适配器实现（可换的那一列）
│   ├── datasource_mock.py     进程内夹具
│   ├── datasource_http.py     真实只读 HTTP
│   ├── storage_local.py       本地目录
│   ├── storage_cos.py         腾讯云 COS
│   └── model_stub.py          脚本化桩（测试用）
└── tools/                     【保留】退化为"只做字段映射"的工具函数
```

### 端口定义（骨架）

```python
# app/ports/datasource.py
from typing import Protocol
from app.models import OrderSnapshot, LogisticsSnapshot, AftersaleSnapshot

class DataSource(Protocol):
    """业务数据源。**只读**；取不到一律返回 None，绝不抛异常。"""

    async def fetch_order(self, order_id: str) -> OrderSnapshot | None: ...
    async def fetch_logistics(self, order_id: str) -> LogisticsSnapshot | None: ...
    async def fetch_aftersale(self, order_id: str) -> AftersaleSnapshot | None: ...
```

```python
# app/ports/storage.py
from typing import Protocol

class ObjectStorage(Protocol):
    """对象存储。

    ⚠️ URL 必须由实现给出（`url_for`）——本地是 /api/seller/uploads/xxx，
    COS 是 https://bucket.cos.region.myqcloud.com/xxx。**调用方不得自己拼 URL**。
    """

    async def put(self, key: str, data: bytes, content_type: str) -> str: ...
    async def get(self, key: str) -> bytes | None: ...
    async def delete(self, key: str) -> bool: ...
    def url_for(self, key: str) -> str: ...
```

```python
# app/ports/factory.py
from functools import lru_cache

@lru_cache(maxsize=1)
def get_datasource() -> DataSource:
    mode = settings.data_source          # 'local' | 'remote'，**无默认值，必须显式配置**
    if mode == "remote":
        return HttpDataSource(settings)
    return MockDataSource()
```

**调用方写法（唯一允许的形式）**：

```python
from app.ports import get_datasource

order = await get_datasource().fetch_order(order_id)
```

### 配置（`.env`）

```ini
# 数据源模式：local=进程内夹具（开发/演示） / remote=真实只读 API（生产）
# ⚠️ 无默认值：未配置则**启动即报错**，绝不允许静默降级
DATA_SOURCE=local

# 对象存储后端：local=本地目录 / cos=腾讯云 COS
STORAGE_BACKEND=local

# 模型后端：stub=脚本化桩（仅测试）/ qwen=真实调用
MODEL_BACKEND=qwen
```

**为什么 `DATA_SOURCE` 不给默认值**：默认值一定会有一侧是错的。
生产默认 `local` → 忘配就跑演示态；开发默认 `remote` → 每次都得去关。
**强制显式声明**，并从根上消灭"我现在跑在哪个模式"这个疑问。

## 六、四条关键工程约束（缺一条，"可插拔"就不成立）

| # | 约束 | 为什么 |
| --- | --- | --- |
| 1 | **契约测试**：同一套用例对**每个适配器各跑一遍** | 这是可插拔能否成立的**关键**。没有它，两个实现会在细节上悄悄分叉，切生产时才发现"字段对不上/语义不同"——那时成本最大 |
| 2 | **URL 由实现给出**（`url_for`），调用方禁止拼 URL | 本地 `/api/...` 与 COS `https://...` 形态不同，散在各处拼必然出错 |
| 3 | **模式在启动日志与健康端点显式暴露** | `/api/health` 加 `data_source` / `storage_backend`；启动打印一行"数据源=local（演示夹具）"。让环境态**看得见** |
| 4 | **失败语义统一**：读失败返回 `None`，绝不抛异常，绝不返回假数据顶替 | 沿用既有红线。降级必须**可见**（日志 + 健康端点），不得静默 |

### 契约测试怎么做

```
tests/contract/test_datasource_contract.py
    ├─ 同一组用例（正常 / 缺失字段 / 空响应 / 超时）
    ├─ 对 MockDataSource 跑一遍        → 必须通过
    ├─ 对 HttpDataSource 跑一遍        → 必须通过（用 httpx mock transport，不打真网）
    └─ 真实 API 的契约用「录制回放」：录一次真实响应存 fixtures，之后离线回放
```

同理由 `storage_local` 与 `storage_cos` 共用一套契约测试（COS 用本地 fake client 或录制回放）。

## 七、一个必须先定的东西：外部契约文档

`app/tools/order.py` 头部现在写着"⚠️ 待与真实接口核对，映射层需按实际字段调整"——
说明**契约目前是假设的**。建议单独落一份：

`docs/契约_外部数据源_v1.md`：逐接口写清 请求路径 / 查询参数 / 响应字段 / 字段语义 / 取值范围 / 失败语义。

**它是"接口的唯一真相"**：Mock 按它造数据、HTTP 适配器按它映射、将来接真实 API 时按它核对。
没有它，"保持接口不变"这句话没有落点。

## 八、迁移路径（低风险，四步）

| 步 | 做什么 | 风险 |
| --- | --- | --- |
| 1 | 落 `docs/契约_外部数据源_v1.md`（把现有假设写实） | 无（纯文档） |
| 2 | 建 `ports/` + `adapters/`，把现有 mock 与 HTTP 逻辑**平移**进去（不改行为） | 低（行为等价搬迁） |
| 3 | `tools/*` 退化为薄封装，调用方改走 `get_datasource()` | 低（有测试兜底） |
| 4 | 补契约测试 + 健康端点暴露模式 + 启动期强校验 | 低 |

**不做的事**：不重写判定链路、不动售后已跑通的逻辑、不引入新依赖（`httpx` / `cos-python-sdk-v5` 按需）。

> COS SDK 是唯一可能需要新增的依赖；若不想装，`storage_cos` 可先用 COS 的 HTTP 签名接口实现（但会多写签名逻辑，**建议直接用官方 SDK**）。

---

## 九、风险与代价

| 风险 | 说明 | 处置 |
| --- | --- | --- |
| **过度抽象** | 抽象层会多一层间接，读代码时多一跳 | 严格按 §四 的边界；只抽三个点 |
| **实现分叉** | 两个适配器行为不一致，切生产才发现 | 契约测试（§六 约束 1） |
| **依赖新增** | COS SDK | 仅在真正接 COS 时才装；现在只留端口与本地实现 |
| **"可插拔"变成借口** | 容易滑向"什么都要能换"，导致配置爆炸 | 只保留 3 个开关；新增开关需先说清"开发与生产为何不同" |

**净收益**：开发期零外部依赖、零流量费；生产切换＝改配置 + 换适配器；
且**因为契约被测试锁住，切换才是真的"替换即可"**，而不是"替换 + 调试一周"。
