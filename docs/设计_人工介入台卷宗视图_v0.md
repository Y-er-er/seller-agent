# 设计 · 人工介入台「卷宗」视图 v0

> **版本**：v0.1（**R1—R6 已裁决并落库**）· **状态**：P0 评审件（与《方案 v3.2》配套）· **本文件不涉及代码**
> **定位**：人工仲裁员的**唯一决策界面**。目标——**仲裁员只凭卷宗就能做决定，不必回看原始系统**。
> **依据**：用户指定卷宗必须包含 ① 对话历史 ② 大模型提取的参数 ③ 命中的规则 ④ 原判定图的逐条依据。


> ⚠️ **对象已调整：人工介入台从「平台侧仲裁员」改为「商家管理员指挥台」；卷宗（事实/证据/疑点/建议）概念保留。**

---

## 一、三条设计原则

| # | 原则 | 具体做法 |
| - | --- | --- |
| 1 | **事实与推断分离** | 规则给出的（命中规则、逐条依据、结论）标为**事实**；模型抽取的参数标为**推断**，并用视觉差异 + 显式声明"不参与判定"隔开。**人不能把推断当依据**。 |
| 2 | **每个字段可回溯** | 结论 → 可点回规则与阈值；模型槽位 → 可点回**对话原话那一轮**；材料 → 可点开原图。**不允许出现"来源不明"的字段**。 |
| 3 | **人工决定必须留痕** | 谁、何时、做了什么决定、**为什么**（理由必填）、以及该决定是否触发资金动作。 |

---

## 二、页面结构（自上而下 9 个分区）

```
┌─ ① 头部：结论摘要条（结论 / 金额 / 已耗时 / SLA 剩余 / 是否挂起）
├─ ② 基本信息（订单、商品、买家、物流、时限）
├─ ③ 疑点与建议（系统疑点 + AI 建议，均标注来源）
├─ ④ 命中规则（事实）
├─ ⑤ 逐条依据（事实，中文化：字段 / 运算符 / 阈值 / 实际值）
├─ ⑥ 大模型提取的参数（推断 · 不参与判定）
├─ ⑦ 对话历史（含每轮工具调用）
├─ ⑧ 举证材料（缩略图 + 校验结果）
└─ ⑨ 审计与用量（审计事件 / 规则版本 / token / 护栏触发）
   底部固定：人工动作区（采纳 / 改判 / 要求补充 / 重试处置 / 关闭）
```

**排序理由**：人的决策顺序是"先看要不要管 → 再看依据 → 再看过程"。**对话历史放在下面**（过程证据），
但它必须是**完整且可检索**的——因为它是判断"智能体问得对不对"的唯一依据。

## 三、字段级定义

### ① 头部摘要条
| 字段 | 示例 | 来源 |
| - | --- | --- |
| 受理号（case_id） | `C-20261014-0007` | 判定图 |
| 结论 | **转人工复核** | 规则引擎 |
| 申请金额 | ¥199.00 | 申请单 |
| 已耗时 / SLA 剩余 | 3h12m / 剩 44h48m | 新增（时限来自补证策略） |
| 当前状态 | 待人工介入 / 待补证 / 已完成 | 判定图 + 对话层 |

### ② 基本信息
订单号、商品（类目/名称）、实付金额、申请退款金额、退款原因、物流状态、签收时间、买家标识（**脱敏**）、历史仅退款笔数（90 天）。

### ③ 风险标签与模型提示（**两个独立分区，严禁混淆**）

**③-A 系统风险标签（事实 · 由规则引擎 R1—R8 自动计算）**

| 示例 | 来源 |
| - | --- |
| 数据不足（订单 / 物流取数失败） | 规则引擎（R8） |
| 举证不完整（0 张有效图） | 举证核验 + 规则引擎（R6） |
| 高频退款（90 天 ≥6 笔 / 退款率 ≥20%） | 规则引擎（R5） |
| 金额达自动处置上限 | 规则引擎（R1） |

> **R3 裁决**：风险标签**只能**来自规则引擎；模型**不得新增、修改或覆盖**这里的任何标签。

**③-B 模型风险提示（推断 · 独立分区）**

| 示例 | 来源 | 呈现 |
| - | --- | --- |
| "对话中出现情绪激动表达" | 模型 | **推断色 + 顶部声明"模型提示，非判定依据，不影响结论"** |
| "买家提到要向平台投诉" | 模型 | 同上 |

> 该分区**与系统标签物理隔开**（不同分区、不同配色），避免人工误把模型提示当成风控标签。

### ④ 命中规则（**事实**）
| 列 | 说明 |
| - | --- |
| 规则 ID / 优先级 | `R1` / 10 |
| 结论 | 转人工复核 / 要求补证 / 自动通过 |
| 规则描述 | 申请金额达到自动处置上限 → 转人工（资金风险闸门） |
| 命中顺序 | 全量求值，**不短路**（故可能同时列出 R1 与 R7） |

> 附：**规则版本号**（`2026.10-final`）——结论可回溯到具体版本的规则表。

### ⑤ 逐条依据（**事实**，最关键的"可解释"部分）
把每条规则的叶子条件展开为**业务语言**：

```
R1（申请金额达到自动处置上限 → 转人工）：申请退款金额 ≥ ¥300.00（实际 ¥1,200.00）
R7（主张质量问题 → 转人工（本方案不做质量判定））：退款原因 = 质量问题
R6（应举证场景但有效举证图为 0 → 要求补证）：有效举证图片数 ≤ 0（实际 0）
```

- 字段名、运算符、枚举值**一律中文化**（`gte`→`≥`、`claim_amount`→`申请退款金额`）；
- 退款率按业务习惯显示百分比（0.20 → 20.0%）；
- 等值比较不重复显示"（实际 质量 = 质量）"这类冗余。

### ⑥ 大模型提取的参数（**推断 · 不参与判定**）
> 顶部固定横幅：**「以下为模型从对话中提取的辅助信息，仅供人工参考，未参与任何判定」**

| 槽位 | 示例 | 需可回溯到 |
| - | --- | --- |
| 诉求分类 | 质量问题（外观） | 对话第 2 轮原话 |
| 问题对象 | 商品本体 / 外包装 / 物流 | 对话第 3 轮 |
| 问题现象 | 污渍、破损 | 对话第 3 轮 |
| 影响数量 | 1 件 | 对话第 4 轮 |
| 期望方案 | 仅退款 | 对话第 1 轮 |
| 签收后时长 | 2 天 | 由订单推断 |
| 已提交材料 | 图片 ×2 | 材料区 |
| 每项附 **置信度** 与 **抽取时间** | 0.86 / 19:22 | — |

> **R2 裁决（重要）**：本分区**只读，不提供任何编辑入口**。
> 人工若发现模型抽错了 → **直接拒绝或转人工**，**不得修改**模型输出。
> 理由：让人工改模型参数会让"推断"污染"事实"，并使留痕口径失效。

### ⑦ 对话历史（**完整会话，可检索**）
每条记录：**角色**（买家 / 智能体 / 系统事件）· **时间戳** · 文本 · 附件引用 ·
以及**本轮触发的工具调用**（可折叠：工具名 / 入参摘要 / 耗时 / 结果摘要）。

**系统事件类型（必须落进历史，不能只写日志）**：
- 转人工（含触发原因：规则命中 / 处置未落地 / **护栏触发**）
- 护栏触发：**轮数达 20 上限** / **单条超 200 字**
- 补证时限提醒与超时
- 结论生成

### ⑧ 举证材料
缩略图（对象存储引用）· 可解码性校验结果 · **视觉信号**（P1 关闭 → 显式显示"未启用"，不留空白）。

### ⑨ 审计与用量
审计事件时间线 · 规则版本 · **模型用量**（模型名 / 轮数 / token / 耗时）· **护栏触发记录**。

### 底部 · 人工动作区
| 动作 | 说明 | 留痕 |
| - | --- | --- |
| 采纳 | 认可规则结论 | reviewer / decided_at |
| **改判** | 给出不同结论 | 上述 + **理由（必填）** + 改判后是否触发资金动作 |
| 要求补充材料 | 回到对话向买家要材料 | reviewer / 要求项 / 时限 |
| 重试处置 | 处置未落地时可用（已有） | reviewer / 尝试次数 / 结果 |
| 关闭 | 结案 | reviewer / 结案说明 |

## 五、需新增/变更的数据结构（仅列清单，不含代码）

## 七、权限与合规（R4—R6 落地）

| 项 | 规则 |
| - | --- |
| **可见范围** | 全量卷宗：**仅平台仲裁员**。商家：仅自己订单的相关片段，**脱敏**（买家标识、联系方式、完整对话中的敏感信息） |
| **导出** | **默认禁止**。需走审批流；批准后仅导出**脱敏文本**，并**加水印**（含导出人 / 时间 / 事由）以便追溯 |
| **对话历史保留** | **90 天**（满足审计与纠纷追溯）；到期转**冷存储**或定期清理，清理须留痕 |
| **脱敏口径** | 买家标识、手机号、地址、支付信息一律脱敏；对话原文仅在授权范围内可见 |
| **审计** | 卷宗的**每一次查看、导出、改判**都必须留痕（谁、何时、看了什么、做了什么） |
