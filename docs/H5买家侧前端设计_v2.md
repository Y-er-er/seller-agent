## 〇、四条判断（决定后面所有设计）

### 0.1 判断 1：问题不是"缺样式"，而是信息架构缺失

v1 的判断，仍然成立：现有页面只有「消息列表 + 输入框」，把买家当成会自己问对问题的专家。
→ **保留工程骨架，重做信息架构**。

### 0.2 判断 2：面向买家的前端**不做任何业务判断**

结论文案、规则→人话、状态推断，全部由后端产出 `view` 视图模型，前端只渲染。
→ 否则同一套口径会散落两处，必然漂移。

### 0.3 判断 3：**不编造任何数据**

P1 没有真实客服排队系统、没有到账时间来源 → `eta_text` 等返回 `null`，页面如实显示"暂无法预估"。
→ **绝不写"预计 5 分钟""1-3 个工作日"**。

### 0.4 判断 4（**v2 新增**）：**智能体必须在页面上"可见"**

**这是 v1 的方向性缺陷。** v1 把页面的可预期部分（进度条、追问卡、结论卡）全设计成**确定性装饰**：

| v1 的设计 | 造成的结果 |
| - | - |
| 固定四步进度「已受理→核实订单→核实物流→给出结论」 | 是**装饰**，与智能体**真实做了什么**无关 |
| 追问卡 = "缺什么问什么" | 看起来像**表单校验器** |
| 快捷选项"后端下发"（未说来源） | 无来源，实际只能是写死的 |
| 结论卡确定性渲染（这条**是对的**） | 但它是**唯一**有内容的东西 |

→ **净效果：买家用起来像一个"表单向导 + 模板回复"的机器人，而不是智能体。**

**正确划分（与项目既有三层归属一致）**：

| 层 | 归属 | 页面上应如何体现 |
| - | --- | --- |
| **过程**（理解 / 工具选择 / 追问 / 冲突澄清 / 收手） | **模型自主** | **必须可见**：动作日志、复述确认、冲突卡 |
| **结论**（定性 / 金额 / 依据） | **确定性代码**（红线：防模型改写） | 结论卡（v1 已对） |
| **呈现**（措辞 / 进度文案） | 可确定性生成 | 只做**脚手架**，不得替代过程 |

> **一句话**：v1 让"确定性"侵蚀了"过程"——**结局**该确定，**过程**必须看得见模型的判断。

## 一、面向买家的智能体能力清单（8 项）

> 判据：**每一项都要能回答"模板/规则做不到什么"**。做不到这一点的，就不是智能体能力。

| # | 智能体能力 | 模板/规则做不到什么 | 当前实现 | 页面上如何可见 |
| - | --- | --- | --- | --- |
| **A1** | **听懂"不像申请"的话**<br>「充电盒盖不上，用了两天就这样」 | 匹配不到"退款/退货"关键词 → 只会答"请描述问题" | ✅ **已具备**<br>（模型理解 + 自主提交判定） | 智能体**复述诉求**："我理解是商品有质量问题，希望退掉并退款" |
| **A2** | **追问因上下文而变** | 缺"签收时间"→ 固定念"请提供签收时间" | ✅ **已具备**<br>（模型自主决定先调 `query_logistics` 再问） | 追问卡**内容来自模型**：<br>"物流显示 10-08 已签收，是这天吗？"——**更容易回答** |
| **A3** | **复述确认（防误判）** | 「退了算了」→ 直接当"仅退款"判下去 | ⚠️ **模型有能力，但提示词未要求、页面无位置** | **确认卡**："我理解你是希望退掉并退款，对吗？"[对] [不是] |
| **A4** | **发现买家陈述与系统事实冲突** | 买家说"没收到"，物流显示已签收 → 继续按"没收到"往下问 | ❌ **未实现**（模型能看到两份事实，但**没要求它处理冲突**） | **冲突卡**："你说没收到，但物流显示 10-08 已签收（可能是驿站代收？）" |
| **A5** | **情绪与对抗处理** | 「你们就是骗子我要投诉」→ 继续问下一题 | ⚠️ 提示词第 5 条覆盖"无法处理→转人工"，**无情绪指引** | 先安抚再看是否继续；或**直接转人工并说明** |
| **A6** | **自主决定何时收手** | 硬等到 20 轮上限 | ✅ **已具备**（自主 `escalate_to_human`） | **主动转人工卡**：说明**为什么**转（"关于是否到货的说法和物流对不上，需要人工核实"） |
| **A7** | **结论后仍可继续对话** | 结论一出就答不了追问 | ⚠️ 循环可继续，但**结论段渲染覆盖了模型话术**，需明确"结论后路由" | 结论卡下方仍可追问："那我什么时候能拿到钱？" |
| **A8** | **不暴露内部、不编造** | 容易把规则代号/阈值念出来；或编造 ETA | ✅ 提示词第 6 条已约束；本设计补前端约束 | 页面**不渲染** `hit_rules`/阈值；无数据源字段显示"暂无法预估" |

**结论**：当前代码**已具备 A1 / A2 / A6 / A8**；**A3 / A5 / A7 差提示词与页面承载**；**A4 是新能力**（需提示词 + 冲突检测 + 页面）。

> ⚠️ **重要**：A3/A4/A5 若要落地，需要**改系统提示词与循环**（属 P1.5 范围），不是纯前端工作。
> 本设计只负责**给出它们的位置与形态**，实现需你批准后单独开工。

## 二、买家旅程（含智能体动作）

```
① 从订单页进入（带 order_id）
   ↓
② 确认订单（这单对不对）                       ← 免建工单的只读预览
   ↓
③ 说问题（一句话 + 可能带图）
   ↓
④ 【智能体】复述确认 ──→ 买家确认/纠正          ← A3，v1 缺失
   ↓
⑤ 【智能体】自主核实：查订单 / 查物流 / 查进度   ← A1 A2，**动作日志可见**
   ↓
⑥ 【智能体】追问（问什么、怎么问，模型决定）     ← A2，**追问卡内容来自模型**
   或 └→ 发现事实冲突 → 冲突澄清               ← A4
   ↓
⑦ 【智能体】判断可以提交 → 提交判定 → 结论由系统给出
   ↓
⑧ 结论呈现（结论卡：定性 + 金额 + 我要做什么）   ← 确定性（红线）
   ↓
⑨ 继续追问 / 转人工（可带理由） / 结束
```

## 三、功能清单

> 优先级：**P1**=本期必做；**P2**=本期可选；**P3**=后续。标 🔶 的是 v2 新增/修正。

### F0 🔶 **智能体可见性（贯穿，本期最高优先）** —— P1

| 项 | 设计 |
| - | - |
| **动作日志** | 智能体每次**真实动作**（调了哪个工具、结果摘要）以**轻量行内条目**出现：<br>`· 正在核实物流信息` / `· 已获取订单：蓝牙耳机 Pro 2 · 已签收 10-08` |
| **来源** | SSE 新增 `action` 事件（来自循环的 `tool_audits`），**不是前端编的** |
| **阶段进度** | 由**动作日志派生**（有几条动作就走到哪），**不再是固定四步装饰** |
| **复述确认** | `view.understanding` 非空时渲染确认卡（A3） |
| **冲突澄清** | `view.conflict` 非空时渲染冲突卡（A4） |
| **转人工理由** | 转人工时必须带 `reason_text`（为什么转），不允许只显示"已转人工"（A6） |
| **边界** | 动作日志**只显示"做了什么"**，不显示工具名、参数原文、内部代号 |

### F1 入口与订单确认 —— P1
（同 v1）主入口带 `order_id` 直接展示订单卡；无单号则手填；订单不存在明确提示；
**订单确认发生在创建会话之前**（`GET /orders/{id}/summary`）。

### F2 会话管理 —— P1
（同 v1）刷新不丢、幂等恢复、终态与 24h 超时处理、会话列表（P2）。

### F3 消息流 —— P1
（同 v1）气泡类型 / 时间分组 / 流式分段 / 失败可重发 / 用户上滑后不抢滚动。

### F4 结构化卡片 —— P1（🔶 扩充）

| 卡片 | 内容 | 触发 |
| - | - | - |
| 订单卡 | 商品 · 单号 · 实付 · 状态 | 常驻 |
| **确认卡** 🔶 | 智能体的理解复述 + [对] [不是] | `view.understanding` |
| **冲突卡** 🔶 | 买家陈述 vs 系统事实的差异 + 请买家解释 | `view.conflict` |
| 追问卡 | 问题 + **为什么要问** + 快捷选项（**内容来自模型**） | 缺必填槽位 |
| **转人工卡** 🔶 | 为什么转 + 接下来会发生什么 | `escalate` 且带理由 |
| 结论卡 | 定性 + 金额 + **我需要做什么** + 后续说明 | 判定完成 |
| 依据折叠 | **买家语言**的理由（不含规则代号/阈值） | 结论卡内，默认收起 |
| 阶段进度 | 由**动作日志**派生 | 处理过程中 |

### F5 追问与快捷回复 —— P1
（同 v1）**追问必须说明用意**；快捷选项由后端下发（追问场景下由模型产出候选，避免写死）。

### F6 举证上传 —— P1
（同 v1）多图、拍照/相册、**前端预校验 + 压缩**、预览、删除、进度、**图片回显**。

### F7 🔶 进度可见 —— P1（**从"固定四步"改为"动作日志派生"**）

- 接收 SSE `action` 事件 → 追加动作条目 + 推进进度；
- **没有动作时不假装有进度**（只显示"正在处理…"）；
- 超过 N 秒无新动作 → "仍在处理，请稍候"（**不假装卡死，也不假装很快**）。

### F8 转人工 —— P1（🔶 加理由）
（同 v1）+ **必须显示转人工原因**（买家语言）+ 转后切留言模式 + **不显示假 ETA**。

### F9 护栏反馈 —— P1
（同 v1）超长（首次/再犯）/ 轮数将尽 / 耗尽 / 成本暂停 / 会话结束，文案各不相同。

### F10 异常与兜底 —— P1
（同 v1）网络 / 503 / 404 三态文案不同；SSE 中断可补齐；已输入内容不丢。

### F11 体验基线 —— P1
（同 v1）点按区 ≥44px、正文 ≥15px、安全区适配、首屏 <1s；深色模式 P3。

### 4.2 🔶 SSE 事件（v2 修订：新增 `action`）

```
event: action   data: { "seq": 2, "label": "正在核实物流信息" }
                       ← 来自循环的 tool_audits，**只给"做了什么"，不给工具名/参数**
event: status   data: { "phase": "verifying_logistics", "label": "正在核实物流…" }
event: meta     data: { …,
   "stream_mode": "segmented",
   "view": {
     "understanding": { "text": "我理解是商品有质量问题，希望退掉并退款", "confirmable": true } | null,
     "conflict": { "buyer_said": "一直没收到货",
                   "system_fact": "物流显示 10-08 已签收（驿站代收）",
                   "ask": "是不是放在驿站或由家人代收了？" } | null,
     "progress": { "from_actions": true },          ← 明示进度来源
     "card": { "type": "decision" | "ask" | "escalate" | "conflict" | "confirm",
               "kind": "refundable" | "need_evidence" | "manual",
               "title": "…", "amount": 199.0, "amount_label": "建议退款金额",
               "buyer_action": "…", "eta_text": null,     ← 无数据源不编造
               "reasons": ["物流显示 7 天前已签收…"],      ← 买家语言
               "reason_text": "…",                        ← 转人工/冲突的原因（买家语言）
               "disclaimer": "…" },
     "quick_replies": ["…"] }, }
event: delta    data: { "text": "…" }
event: done     data: { "chars": 120, "segments": 10 }
event: error    data: { "code": "case_not_found", "message": "…", "status": 404 }
```

> **为什么 `action` 是 v2 的关键**：没有它，页面只能靠**前端编**的假进度；有了它，
> 买家看到的是**模型这一轮真正做了什么**——这才是"智能体可见"。

### 4.3 附件对象化（同 v1）
`{ "attachment": { "id": "<摘要>", "filename": "…", "size": 6322, "content_type": "…", "url": "…" }, "registered": true }`

### 4.4 回显的安全约束（同 v1，四层）
限本会话 / 扩展名白名单 / `inline` + 正确 `Content-Type` / 按 `id` 查登记记录（**不拼路径**）。
