# 契约 · 外部数据源 v1

> **日期**：2026-10-16 · **状态**：**假设契约**（尚未与真实业务系统核对）
> **地位**：本文是外部接口的**唯一真相**。Mock 按它造数据、HTTP 适配器按它映射、接真实 API 时按它逐字段核对。
> ⚠️ **当前所有字段均为假设**（原代码注释已标注"待与真实接口核对"）。接真机时**必须逐项核对并修正本文**，

## 零、通用约定

| 项 | 约定 |
| --- | --- |
| 协议 | HTTPS，`GET`（只读通道） |
| 编码 | UTF-8，`application/json` |
| 超时 | 默认 3s（`http_client._DEFAULT_TIMEOUT`） |
| 并发 | 全局信号量限流，上限 10 |
| **失败语义** | **未配置 / 超时 / 非 2xx / 解析失败 / 字段非法 → 一律返回 `None`，绝不抛异常** |
| 为什么不上抛 | 取数失败交由规则 R8 判「数据不足 → 转人工」，**网络异常不得中断判定链路** |
| 返回值类型 | 顶层必须是 JSON **对象**（数组/标量视为解析失败） |
| 字段缺失 | 用安全转换（`coerce_*`）回落默认值，**不因单个字段缺失整条丢弃**（`order_id` 除外） |

## 一、订单快照

```
GET {ORDER_API_BASE}/orders/{order_id}
```

| 字段 | 类型 | 必填 | 语义 | 取值 / 默认 |
| --- | --- | --- | --- | --- |
| `item_category` | string | 否 | 商品类目 | 缺失 → `""` |
| `pay_amount` | number | **是** | 实付金额（元） | 缺失/非法 → `0.0` |
| `signed_at` | string(ISO8601) | 否 | 签收时间 | 缺失/非法 → `None` |
| `logistics_status` | string（枚举） | 否 | 物流状态 | `not_signed` / `in_transit` / `signed`；非法 → `in_transit` |
| `goods_no` | string | 否 | **该订单对应的商品编号**（卖家控制台 `goods.goods_no`，如 `G-0001`） | 缺失 → `""`（见下方说明） |

> **关于 `goods_no`（2026-10-16 新增）**：
> 商品是**卖家自建**的、订单来自**外部业务系统**，两者本来毫无关联。
> 没有这个字段，「商品 × 售后联动」就算不出"这个商品退货率多少" ——
> **它是两者之间唯一的桥**。真实业务里应由订单系统提供；本地夹具按约定注入。
> 缺失时售后统计会显示"暂无关联工单"，而不是把数据算到别的商品头上。

**响应示例**

```json
{
  "order_id": "O202610130001",
  "item_category": "日用百货",
  "pay_amount": 39.0,
  "signed_at": "2026-10-10T14:22:00",
  "logistics_status": "signed",
  "goods_no": "G-0001"
}
```

**映射落点**：`adapters/mapping.py: to_order()` → `models.OrderSnapshot`

## 四、处置执行（**写通道，语义与上三者根本不同**）

```
POST {DISPOSAL_API_BASE}/disposals
Header: Idempotency-Key: {request_id}
Body:   { "action": "refund", "request_id": "...", "order_id": "...", "amount": 89.0 }
```

| 字段 | 类型 | 语义 |
| --- | --- | --- |
| `status` | string | 受理状态；**仅** `ok` / `accepted` / `success` / `succeeded` 视为受理 |
| `disposal_id` | string | 处置单号（审计留痕用） |

| 与读通道的差异 | 读通道 | 写通道 |
| --- | --- | --- |
| 失败处理 | 返回 `None`，交由规则判"数据不足" | **绝不可当成功**；显式失败并**升级人工** |
| 未配置时 | 回落本地夹具（开发用） | **拒绝执行**（绝不 mock 成功） |
| 幂等 | 不需要 | **必须**：`Idempotency-Key` 防重复退款 |
| 限流 | 共用信号量（上限 10） | **独立信号量**（上限 3），避免与取数抢配额 |

> ⚠️ **写通道不纳入可插拔端口**（见 `设计_可插拔适配层_v1.md`）：
> 它的"未配置即拒绝"与读通道的"未配置即降级"语义**根本相反**，
> 混进同一个 `DataSource` 端口会污染语义。本契约只登记其接口形态，实现保持现状。

## 六、商品只读源（`GoodsSource`）· 2026-10-19 新增

> **状态**：端口与模型已落地，**实现（mock / http 适配器）与同步服务尚未做**。
> 字段同样是**假设**，接真机时逐项核对。

### 6.1 为什么单独一个端口

订单是"来一单查一单"（即时），商品是"批量增量同步"（`updated_since`），
且真实业务里两者常来自**不同系统**（订单 ERP / 商品平台）—— 语义与节奏都不同。

**只读**。写回平台（改价 / 上下架 / 库存）**不在本端口**：多数平台不开放第三方写，
需官方 ISV / ERP 授权。

### 6.2 接口

```python
class GoodsSource(Protocol):
    async def fetch_goods(self, goods_no: str) -> GoodsSnapshot | None
    async def list_goods(self, *, updated_since: datetime | None = None,
                         limit: int = 200) -> list[GoodsSnapshot]
    async def fetch_categories(self) -> list[dict[str, Any]]
```

### 6.3 `GoodsSnapshot` 字段

| 字段 | 类型 | 必填 | 语义 | 取值 / 默认 |
| --- | --- | --- | --- | --- |
| `goods_no` | string | **是** | 平台商品编号（**同步幂等键**） | — |
| `title` | string | 否 | 标题 | 缺失 → `""` |
| `category` | string | 否 | 平台类目，**多级树扁平后的最后一级** | 缺失 → `""` |
| `price_cent` | int | 否 | 售价（**分**） | 缺失 → `0` |
| `list_price_cent` | int | 否 | 划线价（分） | 缺失 → `0` |
| `stock` | int | 否 | 可售库存 | 缺失 → `0` |
| `status` | string | 否 | `on_shelf` / `off_shelf` / `draft` | 缺失 → `""`（按草稿处理） |
| `description` | string | 否 | 商品详情文案 | 缺失 → `""` |
| `images` | string[] | 否 | 图片 URL（**同步时转存**，不直连平台 CDN） | 缺失 → `[]` |
| `updated_at` | datetime | 否 | 平台侧更新时间（**增量同步依据**） | 缺失 → `None` |

### 6.4 同步语义（约定）

| 项 | 约定 |
| --- | --- |
| 方向 | **只读**（平台 → 本地），不做双向同步 |
| 触发 | 拉模式：定时 + 手动「同步」 |
| 粒度 | `updated_since` **增量**（全量在真实店铺拉不动） |
| 冲突 | 平台为准，覆盖 `title/price/stock/category/status/images/description`；**本地独有字段（排序 / 预警线 / 回收站）不动** |
| 覆盖留痕 | 每次同步覆盖写 `operation_log`（`actor=system`），可追溯 |
| 图片 | **转存到自己的存储**（平台 URL 会过期 / 防盗链，且售后统计要长期可查） |

### 6.5 订单快照的 `items`（同批新增）

| 字段 | 类型 | 语义 |
| --- | --- | --- |
| `line_id` | string | 平台订单行 id（售后按行关联时用） |
| `goods_no` | string | 对应卖家控制台的 `goods.goods_no` |
| `sku_id` | string | 平台 SKU（**仅透传**，我们不建 SKU 表） |
| `title` | string | 行商品标题快照 |
| `quantity` | int | 数量（≥1） |
| `unit_price_cent` | int | 单价（分） |
| `paid_cent` | int | 该行实付（分，含优惠分摊） |

> **兼容约定**：`OrderSnapshot.goods_no` / `item_category` / `pay_amount` **保留**，
> 但语义改为「**仅单行订单有效**」；多行订单以 `items` 为准。
> 保留是为了让现有判定链（R1—R11）零改动 —— 属**向后兼容**，不是"两个真相"。
