## 7. 状态机现状

**当前有 2 套正交状态机**（设计上刻意分离，但带来理解成本）：

### 7.1 会话状态机（`conversation_case.status`，7 态）

```
CREATED → CLARIFYING → COLLECTING → SUBMITTED → DECIDED
              └──────────────┴──── ESCALATED / CLOSED（终态）
```
- 合法迁移表 + **三条硬守卫**：终态不再受理 / 成本暂停 / 轮数耗尽
- 升级人工 **7 个触发源**：轮数耗尽 · 字数二次超长 · 成本暂停 · 判定转人工 · 工具连续失败 · 买家主动 · 会话超时

### 7.2 工单状态机（`conversation_case.workflow_status`，5 态）

```
queued → agent_running → awaiting_confirm → resolved
   └──────────→ escalated ←──────────┘
```
- 语义：**谁在处理、指挥到哪一步**

## 12. 最大卡点

按**严重度**排序：

| # | 卡点 | 证据 | 性质 |
| - | - | - | - |
| **1** | **目标漂移** | 4 天 3—4 次改向；8 份方案文档口径互斥 | **根因**——所有其他问题由此派生 |
| **2** | **判定扩展未接通链路** | 诉求方向从未写入 `RefundRequest` → R9/R10 永不命中；指挥台 `intent` 硬编码 `"refund"` | 功能假象（"已完成"不成立） |
| **3** | **确认不执行处置** | `console.confirm()` 仅改状态 | **资金安全**（该退没退、无人跟进） |
| **4** | **合规能力缺失** | 无身份明示 / 内容标识；日志留存 90 天 < 政策要求 180 天 | **法律风险**（政策已明确要求） |
| **5** | **记忆与文档无生命周期** | 旧记忆膨胀至注入上限被截断；文档只增不减 | 知识资产腐化 |
| **6** | **无版本留痕** | git 仅 1 次提交 | 不可回溯，回退成本高 |
| **7** | **测试只覆盖单点、不覆盖链路** | 337 条断言全绿，却存在 5 条断链 | 质量假象 |
| **8** | **数据库账号风险** | 统一用 `root@'%'`（超管 + 弱口令 + 任意主机），`agent_ro` 未建 | 安全 |
