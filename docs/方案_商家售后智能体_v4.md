## 一、定位（一句话）

**面向商家的售后智能体**：买家售后问题实时进入后台收件箱，**管理员指挥**智能体处理指定单，智能体**自主与买家沟通、调工具取证、完成判定（拒绝 / 退款 / 补发）**，关键结果回执给人，人随时可介入。

**这解决了此前的"结构性尴尬"**：模型自主 vs 越权，用「**人在环 + 指挥权在人**」统一——指挥权、介入权、确认权在人，模型只在被授权的范围内自主。

## 二、角色与信息流

```
买家（发售后问题）
   │ 渠道：H5 入口（P1 mock）/ 平台客服（P4）
   ▼
售后问题队列（实时收件箱）
   ▼
管理员指挥台（商家后台，主形态）
   ├─ 指派智能体 / 自己处理 / 随时介入
   ▼
智能体（被指派后接管）
   ├─ 自主与买家沟通（澄清诉求）
   ├─ 自主调工具（查订单 / 物流 / 历史 / 取证）
   ├─ 提交判定（调用规则引擎）
   ▼
判定结果：拒绝 / 退款 / 补发
   ├─ 退款/补发 = 资金/库存动作 → 分级授权 + 人工确认
   ▼
人工兜底：管理员随时接管 / 关键节点确认
```

| 角色 | 职责 |
| - | --- |
| 买家 | 发起售后诉求（退货/退款/补发/投诉） |
| 管理员（商家） | 指挥（指派）、介入、确认判定与资金动作 |
| 智能体 | 被指派后自主沟通、取证、判定、执行（授权范围内） |
| 规则引擎 | 判定唯一来源（模型不参与"赔不赔/赔多少"） |

## 三、判定结果三类：拒绝 / 退款 / 补发

### 3.1 现状

规则引擎结论 `CONCLUSIONS = (auto_pass, auto_reject, request_evidence, to_human)`，处置只有**仅退款**一种。

### 3.2 扩展方案（第一步的内容）

**核心：引入「诉求分类」维度，处置结果 = f(诉求, 结论)。**

| 诉求（claim_type，判定输入） | 结论 auto_pass | 结论 auto_reject | 结论 to_human / request_evidence |
| - | - | - | - |
| 仅退款 | 退款 | 拒绝 | 转人工 / 需补证 |
| 退货退款 | 退货后退款 | 拒绝 | 转人工 / 需补证 |
| 补发 / 重发 | **补发** | 拒绝 | 转人工 / 需补证 |
| 换货 | 换货（P3） | 拒绝 | 转人工 |
| 部分退款 / 补偿 | 补偿（P3） | 拒绝 | 转人工 |

**处置结果枚举（新增）**：`refund`（退款）/ `reship`（补发）/ `reject`（拒绝）/ `manual`（人工）/ `pending_evidence`（需补证）。

**新增规则**（补发判定）：物流损坏 / 漏发 / 少件 → `auto_pass` + 诉求=补发 → 补发。
**拒绝判定**沿用 `auto_reject`（退款率超限、超时效等）。

> ⚠️ **分层原则不变**：`conclusion`（判定结论）与 `disposal`（处置动作）**分开**——
> 结论由规则引擎给，处置由「诉求 + 结论」确定性映射得出，模型不参与。

## 四、指挥协议（人机协同）

| 动作 | 语义 | 触发 |
| - | --- | --- |
| **指派** | 管理员把一笔单交给智能体 | 管理员在收件箱选中单 → 指派 |
| **介入** | 管理员接管，暂停智能体自主 | 管理员随时点击介入 |
| **确认** | 智能体的判定/资金动作须管理员确认（L2）或回执（L1） | 判定完成 / 资金动作发起前 |
| **接管/退回** | 智能体转人工 / 管理员主动接手 | 智能体判 L3 / 管理员介入 |

### 会话状态机（新增，商家侧）

```
待处理(queued) → 智能体处理中(agent_running) → 待确认(awaiting_confirm) → 已完结(resolved)
                        │                              │
                        └──────── 管理员介入(manual) ────┴──── 已转人工(escalated)
```

## 五、执行层红线分级（并入 v0）

| 级别 | 条件 | agent 权限 | 兜底 |
| - | --- | --- | --- |
| **L1 全自主** | 规则 `auto_pass` 且金额 ≤ `AUTO_AMOUNT_CAP`（¥300）且无风险标签 | 直接执行退款/补发 | 审计 + T+1 可撤销 + 抽样复核 |
| **L2 需确认** | 中额 / 首次 / 异常 | 发起动作并挂起，人工确认 | HITL |
| **L3 禁止** | 质量争议 / 大额 / 法律敏感 / 威胁投诉 | 只能转人工 | 人工全权 |

三条硬线：① 规则引擎仍是判定唯一来源；② 执行永不 mock 成功；③ 每笔资金动作幂等 + 可审计 + 可撤销。
