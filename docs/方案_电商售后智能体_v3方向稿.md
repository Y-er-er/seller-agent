## 一、为什么要重定方向

v2.x 交付物经复核，**不具备智能体形态**：

| 判据 | v2.x 事实 |
| - | --- |
| 输入 | 结构化表单；退款原因由前端下拉选择 |
| 控制流 | 11 节点 + 3 条条件边全部硬编码（纯 Python 路由） |
| 工具 | 直接 `await` 函数调用；无 tool schema、无 `bind_tools` |
| 记忆 / 多轮 | 一次 `ainvoke` 跑到 END；检查点存图状态，不是对话 |
| 模型 | `LLM_ENABLED=false`，唯一接入点默认关闭 |
| 前端 | 5 个视图全是**后台控制台**；「提交申请」还需注入 mock，属测试工具 |

**结论**：v2.x 是一套**合格的判定后端**（可复用），但**不是智能体产品**。
问题不在实现质量，而在**产品形态缺失**：没有对话、没有工具自主调用、没有多轮，界面服务的是运营而非当事人。

## 二、目标形态

**一句话**：在**买家的售后流程里**放一个能对话、能查、能取证、能解释、能转人工的智能体；平台侧保留**人工介入台**给仲裁员用。

```
买家侧（对话入口，本次主攻）            平台侧（人工介入台，由现有控制台改造）
┌──────────────────────────┐            ┌──────────────────────────────┐
│ 订单上下文卡片            │            │ 待介入队列                    │
│ 对话流：追问 / 取证 / 解释 │  ──转人工→ │ 卷宗：事实+证据+疑点+建议      │
│ 进度时间线 / 可行动按钮    │            │ 采纳 / 改判 / 要求补充 / 重试   │
└──────────────────────────┘            └──────────────────────────────┘
              ↑                                        ↑
              └──────────── 智能体内核 ────────────────┘
                   对话管理 / 工具调用 / 证据理解 / 记忆
                              ↓ 委托判定
                   规则引擎 + 审计 + 双闸门（v2.x 成果，直接复用）
```

**两个界面职责分明**：
- 对话入口 = **当事人的界面**（买家）；
- 人工介入台 = **人的界面**（仲裁员）——现有控制台改造而来，**不是智能体界面**。

## 三、设计原则（红线，不可让步）

### 3.1 自主性落在「过程」，确定性落在「结论」

| 维度 | 谁决定 | 具体 |
| - | --- | --- |
| 对话 | **模型** | 问什么、怎么问、何时追问、何时结束对话 |
| 取证 | **模型 + 策略** | 要哪些材料、够不够（策略给硬性下限，模型在范围内裁量） |
| 工具 | **模型** | 调什么、调几次（限白名单、限次数） |
| 解释 | **模型** | 用业务语言解释结论与依据（事实必须来自 `hit_details`） |
| **赔不赔 / 赔多少** | **规则 + 人工** | 模型**不参与**；命中红线一律转人工 |
| **资金动作** | **规则 + 双闸门** | 模型**不得**直接触发退款 |

> 这条原则同时满足两个要求：**是真智能体**（过程由模型自主）、**结论可复现**（判定仍由规则给出）。

### 3.2 其余红线（沿用 v2.x）

1. **不做质量判定**：质量问题一律转人工，模型只能描述可见事实。
2. **资金动作双闸门**：`SHADOW_MODE=false` + `DISPOSAL_ENABLED=true` 才具备资格，且带幂等键。
3. **规则引擎不暴露为模型工具**：模型只能"请求判定"，不能"改写规则"。
4. **同输入同结论**：仅约束**判定**；对话过程允许非确定性。
5. **个人信息最小化**：模型调用可全局关闭；图片/对话外送需单独评估。
6. **成本闸门**：`LLM_ENABLED` 总开关 + **P1 护栏参数（已定，见下表）**。

### 3.3 P1 护栏参数（**已定稿，不可放宽**）

| 参数 | 取值 | 触发后的行为 |
| - | --- | --- |
| 模型 | **qwen3.7-plus**（国产高性价比） | — |
| 单会话轮数上限 | **20 轮** | 达上限 → 能给结论就给结论并转人工；否则直接转人工，**必须明确告知「已转人工，请等待」** |
| 单条消息长度上限 | **200 字** | **首次超长 → 提示精简重发（不计轮次）**；**再次超长 → 转人工**（不得因一次粘贴即转人工） |
| 视觉理解 | **P1 关闭**（`VISION_MAX_IMAGES=0`） | P3 单独评估预算 |
| 数据来源 | **mock**，绝不接真实生产库 | P4 前不接 |
| 交互通道 | **网页 H5** | 小程序 / IM 延后到 P4 |
| **月度成本上限** | **¥200** | 达上限 → 停用对话入口（转人工兜底） |
| **预警线** | **¥0.1（等效消耗）** | **达到即立即暂停新会话，并向用户汇报**（防止免费额度耗尽后自动扣费） |
| **免费额度** | qwen3.7-plus **100 万 token（90 天有效）** | **优先消耗**；耗尽后进入现金计费 |

> **成本护栏的最终值待实测后配死**：P1 先跑 **100 次模拟会话**，统计单会话成本的 P50/P95，再倒推月度上限。
> ⚠️ 该实测会**真实消耗免费额度**（不产生现金支出，但在额度内），**执行前需你单独授权**。

> ⚠️ **待澄清（口径）**：¥0.1 预警线是**等效消耗**还是**实际扣费**？
> 免费额度覆盖期间**实际扣费恒为 0** —— 按"实际扣费"计，该预警线**永不触发**；
> 按"等效消耗"（token × 官方单价）计，¥0.1 折算的 token 量级不大 → **一开跑就会暂停**。
> 本稿按「**等效消耗**」处理（只有这样才能起到"防自动扣费"的作用），并把它当作**首次联调保险丝**。
> 若你的本意是"实际扣费达 ¥0.1 才暂停"，请告知，我改成实际扣费口径（届时该线形同不设，需要另设 token 上限兜底）。

> **两条设计裁决（已采纳）**：
> 1. **超长消息不许一票否决**：`>200 字` 首次只提示精简、**不计轮次**；再犯才转人工。
> 2. **轮数耗尽语义写死**：第 20 轮必须"给出结论或转人工 + 明确告知"，绝不能让买家以为还在对话。

## 四、智能体内核设计

### 4.1 双层结构：agentic 外层 + 确定性内层

```
对话循环（模型自主，ReAct 式）
  ├─ 读工具：查订单 / 查物流 / 查画像 / 查口径 / 查进度 / 查历史
  ├─ 写工具（幂等 + 可审计）：登记证据 / 发起补证 / 升级人工 / 催办
  └─ 提交判定 ─→ 【现有确定性图】intake → 取数 → 举证 → judge → risk → dispose → audit
                                    ↓
                            返回：结论 + 命中规则 + 逐条依据
                                    ↓
                        对话层用业务语言解释（事实不可改写）
```

**关键**：v2.x 的整张图从"产品主干"降级为**被智能体调用的一个工具**（`submit_for_decision`）。
这既保住了可复现的判定，又让"调不调、什么时候调"成为模型的自主决策。

### 4.2 会话与数据模型

- **会话 = 工单**：`case_id`（对齐现有"受理号 = thread_id"）；
- **对话历史**落 MySQL 新表（便于运营查询、审计、人工介入台还原），**不塞进图状态**；
- **agent 图的短期状态**（工具调用中间态）走 checkpointer，与判定图分库或分表，互不污染；
- **附件**：证据走对象存储（COS），对话里只存引用。

### 4.3 工具白名单（初稿）

| 类型 | 工具 | 约束 |
| - | --- | --- |
| 读 | 查订单 / 查物流 / 查买家画像 / 查规则口径 / 查工单进度 / 查历史工单 | 只读；异常返回"取不到"，不得编造 |
| 写 | 登记证据 / 发起补证 / 催办 / 升级人工 | 幂等；全部留痕 |
| 判定 | 提交判定（调用现有图） | 一次会话内可重复，但结论由规则给出 |
| **禁止** | 直接退款 / 改规则 / 改阈值 / 访问任意表 | **绝不暴露给模型** |

### 4.4 多轮取证策略（过程自主的落点）

- **策略给下限**：如"质量主张 ≥2 张图 + 1 段视频"、"补证时限 48h"——由配置给出，不由模型临场决定；
- **模型在范围内裁量**：还说"再补一张整体照"还是"够了，提交判定"；
- **催办与超时**：到达时限未补证 → 自动提醒 → 超时升级人工；
- **防止空转**：单会话最大轮数、最大澄清次数（防止模型反复追问）。

### 4.5 记忆

- 会话内：对话历史 + 已提交材料 + 当前阶段（避免重复问同一件事）；
- 跨会话：该买家的历史工单摘要（供风险提示），**但不作为判定依据**。

## 五、产品形态（买家侧对话页）

| 区域 | 内容 |
| - | - |
| 订单上下文 | 商品、订单号、金额、物流状态、剩余时限、申请人——**会话绑定这笔单**，用户不必重复描述 |
| 对话流 | 富消息：文本、图片/视频、金额卡片、方案选项（按钮式澄清） |
| 进度时间线 | 已受理 → 待补证 → 待人工 → 已出结论，每步带时间戳 |
| 可行动区 | 上传证据、查看进度、转人工（随时可用，不需要"问"出来） |
| 转人工 | 带上完整上下文（对话摘要 + 材料 + 疑点 + 规则依据），人工不必再问一遍 |

**与 v2.x「口径问答」tab 的关系**：该 tab 是过渡产物（"背答案的 FAQ"），**并入对话入口**后删除。

## 六、人工介入台（现有控制台改造）

保留现有 5 视图中的 4 个（待复核 → **待介入**、审计查询、统计看板、配置），改造要点：

1. **队列项扩展为「卷宗」**：对话摘要 + 已提交材料（可预览）+ 命中规则与逐条依据 + 疑点 + AI 建议；
2. **会话还原**：能看到买家与智能体的完整对话（判断"问得对不对"）；
3. **人工动作**：采纳 / 改判 / 要求补充材料 / 重试处置（已有）；
4. **移除**「提交申请」视图（那是测试工具，改由对话入口驱动）。

| - | --- | --- |
